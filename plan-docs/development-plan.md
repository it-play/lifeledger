# omega-dream 개발 계획

> 모의 자산 관리 인생 시뮬레이션 웹게임. 실제 금융 제도와 시장 통계를 기반으로 돌지만
> 플레이어의 자산만 가상이다. 비상업적 개인 프로젝트.

- 최초 작성: 2026-07-25
- 상태: 초안 (아키텍처 확정, 구현 착수 전)

---

## 1. 제품 개요

플레이어는 **캐릭터를 생성해 시작 조건을 직접 정하고**(나이·성별·출신·시작 자금·부채 등, §3),
그 조건에서 증권·연금·부동산·현물·예금 등에 자산을 배분하며 불려 나간다.
그 위에 취업·법인 설립·개인파산 같은 생애 이벤트와, 그 이벤트를 가능하게 하는 개인 스펙
(학력·자격증·연수·경력·프로젝트)이 얹힌다. 인생게임이지만 무게중심은 **자산 관리**에 있다.

### 핵심 재미

1. **실제 제도를 이용한 최적화** — ISA·연금저축·IRP의 한도와 세제 혜택을 조합해 세후 수익을 끌어올리는 재미
2. **시장 사이클 경험** — 금리 인상기·침체·회복이 자산군별로 다르게 작용하는 것을 체감
3. **인적 자본과 금융 자본의 상호작용** — 스펙에 투자해 소득을 올리는 것과 금융에 투자하는 것 사이의 배분
4. **다른 출발선 다시 살기** — 19세 고졸 무자본과 38세 부채 보유자의 최적해는 완전히 다르다. 리플레이의 동력

### 비범위 (이 프로젝트가 하지 않는 것)

- 실제 금전 거래, 실제 주문 체결, 실제 계좌 연동
- 투자 조언 · 수익률 예측 제공
- 특정 금융회사 상품의 광고 또는 비교 추천

## 2. 확정된 핵심 설계 결정

| 항목 | 결정 | 근거 |
|------|------|------|
| 시간 모델 | **상시 진행 (가속 배속)** | 오프라인에도 세계가 흐름. 방치형 재미 + 장기 축적 자산(연금·부동산) 체감 가능 |
| 월드 클록 | **전 플레이어 공유 단일 클록** | 시장이 공유되어야 랭킹 비교가 성립. 시세 생성이 1회로 끝나 부하도 낮음 |
| 기본 배속 | **게임 1일 / 실제 1분** (1440:1, 설정값) | 게임 30년 ≈ 실제 21일. 조정 가능하게 설정으로 뺌 |
| 시뮬레이션 해상도 | **게임 1일 봉** (장중 틱 없음) | 자산 배분 게임에 초 단위 호가는 불필요. 부하·복잡도 절감 |
| 시작 조건 | **프리셋 + 포인트 예산 내 커스텀** (§3) | 자유 입력만 두면 밸런스가 붕괴. 랭크/샌드박스 모드 분리 |
| 실제 수치 | **3자 혼합** — 과거 시계열로 모델 캘리브레이션 + 외부 API로 현재값 앵커링 + 제도·상품 스펙은 실제 규정대로 | 재현성·법적 안전성·현실감을 동시에 확보 |
| 저장·계정 | **서버 계정 + PostgreSQL** | 서버가 세이브와 정산의 권위. 랭킹·치팅 방지·기기 간 이어하기 |
| 시뮬레이션 권위 | **서버 단독** | 클라이언트는 표현만. 금액 계산을 클라이언트에 두면 조작 가능 |

### 공정한 비교라는 문제

두 겹의 불공정이 있다. **(a)** 공유 클록이라 나중에 시작한 플레이어는 세계 중간에 합류한다.
**(b)** 시작 조건이 커스텀이라 출발선 자체가 다르다.

- (a) → 랭킹은 절대 자산이 아니라 **경과 게임연수 대비 세후 CAGR**로 정규화
- (b) → **프리셋별 리그를 분리**한다. 난이도 계수를 곱해 하나의 표에 섞는 방식보다 단순하고 납득 가능하다.
  포인트 예산으로 커스텀한 캐릭터는 예산이 같은 리그에 들어가고, 샌드박스는 랭킹에서 제외

## 3. 캐릭터 생성 (시작 설정)

시작 조건은 이 게임의 리플레이 축이다. **자금 1,000만원은 기본 프리셋의 값일 뿐 고정값이 아니다.**

### 3.1 시작 파라미터

| 파라미터 | 범위 | 게임 내 영향 |
|----------|------|--------------|
| 나이 | 19 ~ 50 | 남은 경제활동 기간, 청년 대상 정책상품 자격, 연금 수령 개시까지의 기간, 채용 공고 연령 밴드 |
| 성별 | 남 / 여 / 기타 | **제도적으로 실재하는 차이에만 연결** (§3.4) |
| 병역 상태 | 미필 / 복무중 / 필 / 면제 / 특례복무 | 채용 공고 자격 제약, 경력 공백, 복무 기간 소득·자산 제약 (§8.1) |
| 출신 지역 | 수도권 / 광역시 / 중소도시 / 군 | 부동산 가격대, 공고 풀(사랑방 유효성), 생활비 수준 |
| 가정 배경 | 지원형 / 독립형 / 부양형 | 부모 지원금 수령, 부양비 고정 지출, 상속 이벤트 확률 |
| 학력 | 고졸 ~ 박사 | 초기 스펙, 학자금 부채와 연동, 초임 밴드 |
| 경력 | 0 ~ n년 | 시작 연봉 밴드, 경력직 공고 접근 |
| 보유 자격증 | 0 ~ n | 초기 스펙 |
| 시작 자금 | 0 ~ 예산 상한 | 현금·예금 배분 상태로 지급 |
| 시작 부채 | 학자금 / 신용 / 전세대출 | 원리금 상환 스케줄, 신용점수 초기값, DSR 여력 |
| 건강 | 상 / 중 / 하 | 의료비 이벤트 확률, 보험료율 |
| 부양가족 | 0 ~ n | 고정 지출 증가, 소득공제 증가 |

### 3.2 밸런스 — 포인트 예산

자유 입력만 허용하면 "시작 자금 100억 / 부채 0 / 19세"가 유일해라서 게임이 성립하지 않는다. 두 모드로 나눈다.

- **랭크 모드** — 프리셋을 고르거나, 포인트 예산 안에서 트레이드오프로 배분한다.
  자금을 올리면 나이·부채·건강·부양가족에서 대가를 치른다. 예산이 같은 캐릭터끼리 같은 리그
- **샌드박스 모드** — 모든 값 자유 입력. 랭킹 제외. 제도 실험용

### 3.3 프리셋 (초기 제공안)

| 프리셋 | 나이 | 학력 | 시작 자금 | 부채 | 배경 | 성격 |
|--------|:---:|------|-----------|------|------|------|
| 사회초년생 | 25 | 학사 | 1,000만 | 학자금 2,000만 | 독립형 | 기본값. 균형 |
| 이른 출발 | 19 | 고졸 | 200만 | 없음 | 부양형 | 시간은 많고 자본은 없음 |
| 늦은 출발 | 38 | 학사 | 5,000만 | 신용 3,000만 | 독립형 | 자본은 있고 시간이 짧음 |
| 지원 받는 출발 | 25 | 석사 | 3억 | 없음 | 지원형 | 쉬운 난이도. 세제 한도 최적화가 주 과제 |
| 재기 | 45 | 고졸 | 0 | 회생 이력 | 독립형 | 신용 제약 하에서의 복구 플레이 |

수치는 플레이테스트로 조정한다. 프리셋도 콘텐츠 데이터로 관리해 코드 수정 없이 추가한다.

### 3.4 성별 처리 원칙

성별은 **제도적으로 실재하는 차이에만** 연결한다.

- 병역 대상 판정 (§8.1) → 복무 기간이 경력 공백·자산 공백으로 반영
- 출산·육아 관련 제도 (육아휴직 급여, 관련 공제)
- 성별에 따라 산정되는 보험료율

반대로 **채용 확률·연봉에 성별 계수를 직접 넣지 않는다.** 현실의 격차를 재현한다는 명목으로
차별을 게임 규칙으로 고정하는 것은 이 프로젝트가 할 일이 아니다. 격차를 다루더라도
제도(경력 단절, 휴직)를 통해 간접적으로 드러나게 한다.

### 3.5 정합성 검증

시작 파라미터는 서로 모순될 수 있어 서버에서 조합을 검증한다.

- 나이 ↔ 병역 상태 (19세 "필" 불가, 40세 "미필"은 사실상 면제 처리)
- 나이 ↔ 학력 ↔ 경력 (합계가 나이를 넘지 못함. 학업 기간 + 복무 기간 + 경력 ≤ 나이 − 취학 연령)
- 학력 ↔ 학자금 부채 (고졸에 학자금 대출 없음)
- 병역 특례복무 ↔ 자격증·학력 요건 (§8.1)

검증 실패 시 캐릭터 생성을 거부하고 어떤 조합이 모순인지 알려준다.

## 4. 시스템 아키텍처

```
client/  (webpack, 정적 SPA)
   │  REST (조작·조회) + SSE (시세·이벤트 푸시)
   ▼
server/  (Rust, axum)
   ├── api          HTTP 핸들러, 인증, 검증
   ├── world        월드 클록, 틱 스케줄러, 정산 큐
   ├── character    캐릭터 생성, 프리셋·포인트 예산 검증
   ├── market       거시·주식·금리·부동산·현물 시뮬레이션 엔진
   ├── product      계좌·금융상품 규칙 (CMA/ISA/IRP/연금저축/예적금…)
   ├── tax          세금·공제·4대보험 계산 (제도 버전 기반)
   ├── career       스펙·이력서·채용 매칭·급여
   ├── life         지출·생애 이벤트·파산/회생·복지 자격 판정
   ├── corp         법인 설립·단순 경영 손익
   └── store        PostgreSQL (sqlx) 접근 계층
   ▼
PostgreSQL  ── 세이브 상태 · 시세 시계열 · 제도 룰 데이터 · 감사 로그
```

### 기술 스택

| 계층 | 선택 | 비고 |
|------|------|------|
| 서버 | Rust 1.97.1, axum 0.8, tokio | 이미 스캐폴딩됨 (`server/`) |
| DB | PostgreSQL + sqlx | 시계열 볼륨이 커지면 파티셔닝 검토 |
| 클라이언트 | webpack 5 (현재 vanilla JS) | **§11 미결정 1번** — 게임 UI 규모상 재검토 필요 |
| 인증 | 이메일+비밀번호(Argon2id) 세션 쿠키 | OAuth는 후속 |
| 배포 | 미정 | 단일 컨테이너 + Postgres로 시작 |

### 월드 틱 파이프라인

실제 1분마다 스케줄러가 게임 1일을 전진시킨다.

1. **거시 갱신** — 레짐 전이 판정, 기준금리·CPI·성장률 업데이트
2. **시장 갱신** — 자산군별 일봉 생성 (§5), `market_daily`에 적재
3. **평가** — 전 플레이어 포지션 재평가
4. **정산** — 이자·배당·임대료·급여·지출·세금·대출 상환 (해당 게임일에 걸린 것만)
5. **이벤트** — 생애 이벤트 추첨, 채용 결과 판정, 복지 자격 재평가
6. **푸시** — SSE로 접속 중인 클라이언트에 델타 전송

플레이어별 반복 없이 처리하기 위해 정산은 **큐 기반**으로 둔다 (`scheduled_settlement` 테이블에
게임일 기준으로 예약, 해당 일에 배치 처리). 오프라인 플레이어도 같은 큐로 처리되므로
"오프라인 정산" 별도 경로가 필요 없다.

## 5. 시장 시뮬레이션 엔진

목표는 "현실과 통계적으로 닮은" 시장이다. 실제 시세를 그대로 흘리는 것이 아니라,
**과거 데이터에서 추정한 파라미터로 생성**한다. 이 선택이 §10의 데이터 재배포 문제를 동시에 해결한다.

### 5.1 거시 레짐 (모든 자산의 공통 동인)

4상태 마르코프 체인: `확장 · 둔화 · 침체 · 회복`. 전이확률은 과거 경기순환 데이터로 추정.
레짐이 기준금리·물가·성장률의 드리프트를 결정하고, 그것이 아래 모든 자산군에 전파된다.

### 5.2 자산군별 모델

| 자산군 | 모델 | 주요 특성 |
|--------|------|-----------|
| 주식 (지수) | 레짐별 드리프트·변동성 + 변동성 클러스터링(GARCH 계열) | 침체기 하락 + 변동성 급등을 재현 |
| 주식 (개별) | 시장 팩터 + 섹터 팩터 + 개별 특이수익 | 베타·섹터 로테이션·분산 효과가 자연히 생김 |
| ETF | 기초지수 추종 + 보수·추적오차 | 국내/해외/채권/금 ETF |
| 금리·채권 | 단기금리 확률과정(Vasicek 계열) + 기간구조 → 채권가격 | 금리 인상기 채권 손실을 체감 |
| 예적금 | 기준금리 + 상품별 가산금리 스프레드 | 실제 금리 분포에서 추정한 스프레드 |
| 부동산 | 지역별 평균회귀 + 금리·공급 충격 + 전세가율 | 거래비용 크고 매도에 지연이 있음 |
| 현물 (금·은) | 실질금리 역상관 + 달러 연동 | 위기 시 헤지 성격 |
| 환율 | USD/KRW 확률과정 | 해외자산 수익률에 반영 |
| 물가 | 레짐 연동 CPI | 생활비·실질수익률에 반영 |

자산 간 상관은 개별로 지정하지 않고 **공통 팩터(레짐·금리·환율)를 통해 유도**한다.

### 5.3 캘리브레이션과 검증

- **캘리브레이션**: 과거 시계열로 연평균 수익률·변동성·레짐 전이확률·상관 추정 → 파라미터를 버전 있는 데이터로 저장
- **앵커링**: 외부 API로 받은 현재 기준금리·물가·지수 수준을 시뮬레이션 시작점으로 사용
- **검증 (자동 테스트)**: 장기 시뮬레이션을 다수 시드로 돌려 연평균수익률·변동성·최대낙폭·자산 간 상관이 역사적 범위 안에 들어오는지 통계 검정
- **재현성**: 시드 고정 시 완전 결정론적. 버그 재현과 리플레이에 필수

## 7. 커리어와 개인 스펙

### 7.1 스펙 모델

| 항목 | 내용 |
|------|------|
| 학력 | 고졸 / 전문대 / 학사 / 석사 / 박사. 진학은 비용·시간 투자 (시작 시 선택 가능, §3) |
| 자격증 | 취득 조건(응시자격·학습시간·응시료), 직무별 가중치 |
| 어학 | 점수 구간, 유효기간 |
| 연수·교육 | 국비 지원 과정(고용24 연계)과 자비 과정 |
| 경력 | 직무별 연차. 경력이 연봉 밴드와 매칭 확률을 올림 |
| 프로젝트 | 포트폴리오 항목. IT·크리에이티브 직무 가중 |

시작 설정의 학력·경력·자격증은 이 스펙 테이블의 초기값으로 그대로 들어간다.
스펙은 **포트폴리오 / 이력서 / 링크드인 프로필** 세 가지 산출물로 조합되어 채용 매칭에 쓰인다.

### 7.2 구직 플랫폼

같은 공고 풀을 쓰지 않고 플랫폼마다 성격을 다르게 한다 — 어디를 쓰느냐가 선택이 되도록.

| 플랫폼 | 성격 | 게임 내 차별 요소 |
|--------|------|-------------------|
| 사랑방 | 지역 밀착, 중소·생산직 비중 | 지역 한정 공고, 빠른 채용. 출신 지역(§3)과 연동 |
| 잡코리아 | 전 업종 대량 | 공고 수 많고 경쟁률 높음 |
| 사람인 | 전 업종 대량 | 이력서 열람 기반 역제안 |
| 원티드 | IT·경력직 | 추천·리퍼럴 보너스, 합격 시 보상 |
| 링크드인 | 외국계·헤드헌팅 | 프로필 완성도가 인바운드 제안 확률을 결정 |
| 고용24 | 공공 연계 | 국비 훈련, 실업급여, 국민취업지원제도 등 제도 접근 창구 |

**매칭 로직**: 공고 요구 스펙과 플레이어 스펙의 적합도 점수 → 서류 통과 확률 → 면접 판정 → 연봉 밴드 내 오퍼.
초기 구현은 **업종 5~7개 중 선택해 취업하는 단순 버전**으로 두고, 공고·자격증 콘텐츠는 이후 채운다.

### 7.3 소득

급여는 4대보험·소득세 원천징수를 거쳐 세후로 입금되고, 연말정산에서 세액공제(연금저축·IRP 등)가 정산된다.
**여기서 §6의 세제 혜택과 연결되는 것이 이 게임의 핵심 루프다.**

### 8.1 병역

한국 배경의 인생게임에서 병역은 **20대 초반 몇 년의 소득·경력·자산 축적을 통째로 결정**하는 변수다.
단순 공백이 아니라 선택지가 있는 시스템으로 다룬다.

| 복무 형태 | 요건 | 게임 내 효과 |
|-----------|------|--------------|
| 현역 | 기본 | 복무 기간 경력 공백, 병사 봉급 수준의 소액 소득, 자산 운용은 계속 가능 |
| 사회복무요원 | 신체등급 판정 | 출퇴근이라 복무 중 학업·자격증 취득 병행 가능 |
| 산업기능요원 | 자격증 + 지정업체 취업 | **복무 기간이 경력으로 인정** — 자격증 선투자가 커리어 가속으로 돌아오는 트랙 |
| 전문연구요원 | 석사 이상 | 학력 투자 트랙. 연구 경력 인정 |
| 장교·부사관 | 학력·선발 | 복무 기간이 길지만 급여가 병사보다 훨씬 높음 → 초기 자본 형성 경로 |
| 면제 | 신체·기타 사유 | 공백 없음. 캐릭터 생성 시 선택 가능하되 포인트 예산에서 대가 |
| 미필 유지 | — | 일부 공고가 "병역 필 또는 면제"를 요구해 **채용 풀이 좁아짐**. 나이가 차면 압박 증가 |

**자산 게임과 연결되는 지점**

- **장병내일준비적금** — 복무 중 납입에 정부 지원금이 매칭되는 정책상품. 소득이 거의 없는 시기에
  자산을 만드는 거의 유일한 수단이라, "복무 기간을 어떻게 쓰느냐"가 첫 최적화 문제가 된다
- 복무 기간에는 근로소득이 사실상 없으므로 **세액공제(연금저축·IRP)의 효용이 낮다** — 세제 혜택이
  소득 수준에 따라 달라진다는 것을 배우는 첫 사례
- 산업기능요원·장교 트랙은 스펙 선투자(자격증·학력)가 소득·경력으로 회수되는 구조라 §7과 직결

**예비군·민방위**는 연간 소액의 시간 비용으로만 반영한다 (세부 구현 불필요).

### 8.2 복지·정책상품 판정 엔진

복지상품은 **자격 조건 판정 엔진**으로 일반화한다 (나이·소득분위·재산·가구원·근로형태·병역 상태 조건의 조합).
개별 상품을 하드코딩하지 않고 조건식 데이터로 두면 콘텐츠 추가가 데이터 작업이 된다.
캐릭터 생성 시의 나이·지역·가구 구성·병역 상태가 곧바로 이 판정의 입력이 된다.

수집은 오프라인 배치로 돌려 원시 데이터를 저장하고, 여기서 파라미터를 추정해 **파라미터만 게임에 투입**한다.

### 9.2 외부 API (현재값 앵커링)

시뮬레이션 시작점과 주기적 보정에만 쓴다. 어댑터 인터페이스로 감싸고 **장애 시 마지막 캘리브레이션 값으로 폴백**한다.
게임 진행이 외부 API 가용성에 의존하지 않는 것이 요구사항이다.

### 9.3 콘텐츠 데이터 (나중에 채움)

자격증 목록, 채용 공고 템플릿, 업종·직무 분류, 복지상품 조건, 지역 정보, 캐릭터 프리셋.
전부 시드 데이터 파일로 관리해 게임 로직 수정 없이 추가할 수 있게 한다.

## 10. 법적 · 윤리적 고려

비상업적 개인 프로젝트라 부담은 작지만, 실제 이름을 쓰는 만큼 짚어둘 것이 있다.

1. **시세 데이터 재배포** — 거래소·벤더 데이터는 재배포가 제한되는 경우가 많다. 이 설계는 외부 원시 시세를
   클라이언트로 그대로 내보내지 않고 **서버 내부 캘리브레이션에만 사용**하며, 플레이어가 보는 시세는
   시뮬레이션 산출물이다. 구현 시 각 API 이용약관을 개별 확인한다.
2. **상표** — 잡코리아·사람인·원티드·링크드인·사랑방·고용24 등은 타사 상표다. 서비스를 지칭하는
   명목적 사용에 한정하고, **로고·UI 모방은 하지 않으며, 제휴·후원 관계가 없다는 고지**를 넣는다.
   금융상품명도 마찬가지(제도 일반명 우선, 특정 회사 상품명은 회피).
3. **투자 조언 오인 방지** — "교육·오락 목적의 시뮬레이션이며 투자 조언이 아니고, 시세는 실제가 아닌
   생성 데이터"라는 고지를 상시 노출한다.
4. **차별 재현 회피** — §3.4. 성별·출신을 결과에 직접 곱하는 계수로 쓰지 않고, 제도를 통해 간접적으로만 반영한다.
5. **개인정보** — 계정은 이메일·비밀번호 해시만. 실명·주민번호·실제 금융정보는 수집하지 않는다.
6. **도박성 회피** — 실제 금전 투입·환전 경로를 만들지 않는다.

## 11. 미결정 사항

1. **클라이언트 스택** — 현재는 HTML5 Boilerplate + vanilla JS. 계좌·차트·이력서·공고 목록·캐릭터 생성 등
   상태가 많은 화면 규모를 vanilla로 감당하기는 어렵다. **권장: TypeScript 도입 + 경량 프레임워크 선택**.
   결정 시점은 M1 UI 착수 전.
2. **시작 시점** — 과거 특정 연도에서 출발(역사 리플레이 느낌)할지, 현재 시점에서 출발할지.
   §5가 생성 모델이라 둘 다 가능하다.
3. **배속 값** — 1440:1이 방치형으로 적절한지는 플레이테스트로 조정.
4. **포인트 예산 설계** — 파라미터별 환산 비용을 어떻게 매길지. 밸런싱의 핵심이라 플레이테스트 의존도가 높다.
5. **캐릭터 수명 처리** — 사망·정년 이후를 엔딩으로 끊을지, 연금 수령기까지 계속 돌릴지. 목표 나이 도달 시
   결산 리포트를 주는 방식이 유력.
6. **시즌제 도입 여부** — 프리셋별 리그로 충분한지, 고정 기간 시즌 리그가 필요한지.
7. **배포 환경** — 상시 틱이 돌아야 하므로 서버리스는 부적합. 상시 구동 호스팅 필요.

| **M0 기반** | 서버 스캐폴딩(완료), DB 스키마, 인증, 월드 클록 틱, SSE 골격, **캐릭터 생성(프리셋만)** | 계정 생성 → 프리셋 선택 → 게임 시간이 흐르고 클라이언트에 보임 |
| **M1 시장 코어** | 거시 레짐, 주식·금리 모델, 일봉 생성, 캘리브레이션 배치, 차트, 현금·주식 매매 | 시작 자금으로 주식을 사고 시세가 통계 검증을 통과 |
| **M2 계좌·세제** | CMA·예적금·ISA·연금저축·IRP·채권·금, 세금 엔진, 정산 큐, 금융소득종합과세 | 세제 혜택 계좌 조합에 따라 세후 수익이 달라지는 것이 검증됨 |
| **M3 커리어** | 스펙, 포트폴리오·이력서·링크드인, 6개 플랫폼, 단순 취업(업종 선택), 급여·연말정산, **병역(복무 형태·장병내일준비적금)** | 미필로 시작해 복무를 마치고 취업 → 급여로 연금 납입 → 세액공제까지 한 바퀴 |
| **M4 생애** | 지출, 부동산·대출(시작 부채 포함), 복지상품 판정, 파산/회생, 생애 이벤트, 법인 설립(단순) | 파산과 재기를 포함한 30년 플레이가 끝까지 돌아감 |
| **M5 확장** | **포인트 예산 커스텀·샌드박스 모드**, 콘텐츠 채우기(자격증·공고·업종·프리셋), 랭킹·리그, 법인 경영 세부화 | 외부 플레이테스트 가능 |

각 마일스톤은 `plan-docs/`에 세부 스펙 문서를 별도로 추가한다 (이 문서는 상위 계획만 유지).
